Revisão Modelagem Relacionals

Na modelagem relacional, alguns conceitos mudam:

  • Linha -> Tupla

  • Coluna -> Atributo

  • Tabela -> Relação

  • Dados que especifica o tipo de valores em um atributo -> Domínio

As relações podem possuir diferentes chaves. As mais comuns são:

  • Chave primária: Identifica unicamente cada tupla e é identificada pelo sublinhado;

  • Chave estrangeira: Após definir a Relação, identificamos a chave estrangeira:

<nome_da_coluna> referencia <nome_da_tabela>

Por exemplo:

Empregado( Matrícula , Nome, Endereço, Função, Salário, Dep)

<Dep> referencia <Departamento>

Departamento(CodDepart, Nome Endereço)

Neste caso, o atributo Dep na relação Empregado é uma chave estrangeira da relação Departamento. E como podemos ver, ela sempre irá se referenciar a chave primária da outra relação.

Restrições

Busca assegurar a restrições dos dados. Temos cinco restrições:

  1. Chave: Deve ser um valor único; (é uma definição de Modelo Relacional)
  2. Entidade: Chave primária não pode ser nulo;
  3. Vazio: Define se a coluna tem ou não que ser preenchida (vazia);
  4. Domínio: Deve obdecer as definições estabelecidas;
  5. Referencial: É a restrição que define que os valores da chave estrangeira deve aparecer na chave primária. É a restrição mais importante.

Operações

  • Recuperação: consulta dados

  • Atualização: muda os estados das relações

Atualização:

  • Inserir

  • Excluir

  • Alterar

As operações não devem violar as restrições de integridade.

Inserir:

inserir <valor1, valor2, valorn> em R

Se acontecer alguma violação de integridade, o Modelo Relacional prevê duas opções:

  • Opção Padrão: Rejeitar a inserção, uma vez que viola a restrição que mantém a integridade dos dados;

  • Opção alternativa: Corrigir o motivo da rejeição

Excluir:

Especificamos uma condição sobre os atributos que, partindo da condição definida, irá selecionar as tuplas que serão excluídas:

Exluir tupla em R com atributo1 = valor1 e atributo2 = valo2

Se houver violação de integridade, há duas opções:

  • Restrict: rejeitar a exclusão;

  • Cascade: tentar propagar a exclusão, excluíndo tuplas que a referenciam;

O Cascade é perigoso, uma vez que pode ser propagado alterações (exclusão) até que as restrições não sejam mais violadas, excluíndo atributos que deveriam ser mantidos.

  • Set null/default: modificam os valores de atributo que referenciam a causa da violação;

    Por exemplo, se tentar apagar um funcionário que possui dependente, podemos “setar” um valor de funcionários na relação Dependentes só para permitir a operação.

  • Pode também haver uma combinação das 3. Porém, o mais adequado é o Restrict.

Alterar:

Usado para alterar valores em uma tupla que já existe, segundo uma condição que queremos:

Alterar atributo_alvo da tupla em R com atributo_cond = valor_cond para valor_alvo

Se formos mexer em um atributo que não faz parte de chave primária ou chave estrangeira, possivelmente não terá problemas.

Em caso de violação de restrição, recai sobre os casos do Inserir ou Excluir, precisando fazer o tratamento da alteração.

Conceitos iniciais de SQL

SQL vem de Structured Query Language e é a linguagem padrão em Sistemas Gerenciadores de Banco de Dados (SGBDs) devido a sua simplicidade e facilidade de uso.

É uma linguagem declarativa, ou seja, indica o que consultar, e não como.

Para trabalhar nos diferentes SGBDs, cada um possui pacotes adicionais ao núcleo da Linguagem SQL. Ela por si só possui tem uma definição de como foi desenvolvida, mas os SGBDs podem ir acrescentando algumas operações.

Com o SQL, conseguimos definir a estrutura dos dados, realizar consultas, realizar atualizações e controle de acesso ao BD, tudo isso através das sublinguagens que o SQL nos fornece:

  • DDL

  • DML

  • DQL

  • VDL

  • DCL

Além disso, é possível incluir SQL em código de programação genérica, e por isso, é amplamente utilizado.

A primeira sublinguagem é a DDL

DDL: Data Definition Language

Ela tem como objetivo a criação, alteração e remoção de objetos do BD (esquemas, tabelas e atributos). Exemplo:

CREATE TABLE EMPREGADOS(
    NOME VARCHAR(100) NOT NULL,
    CPF VARCHAR(11) PRIMARY KEY,
    DATANASC DATE,
    ENDERECO VARCHAR(30),
    SEXO CHAR,
    SALARIO DECIMAL(12,2),
    SUPERCPF VARCHAR(11) REFERENCES EMPREGADO(CPF),
    DNO INT NOT NULL REFERENCES DEPARTAMENTO(DNUM)
);

Para alterar, utilizamos o comando ALTER TABLE:

ALTER TABLE EMPREGADOS RENAME TO EMPREGADO;
ALTER TABLE EMPREGADO ADD COLUMN FUNCAO TYPE VARCHAR(50);
ALTER TABLE EMPREGADO DROP COLUMN SALARIO;
ALTER TABLE EMPREGADO ALTER COLUMN ENDERECO TYPE VARCHAR(50);

Para remoção de uma tabela, usamos o DROP TABLE:

DROP TABLE EMPREGADO

Ou seja, para mexer na estrutura dos meus dados, precisamos do DDL.

DML: Data Manipulation Language

É utilizada para manipular os dados. Ou seja, inserir, remover ou alterar linhas de uma tabela. Para isso, usamos comandos como:

INSERT
DELETE
UPDATE

DQL: Data Query Language

Basicamente reune os comandos para seleção de dados, ou seja, comandos de consulta no Banco de Dados. O mais comum é:

SELECT FROM

Alguns livros jutam o DML com o DQL.

VDL: View Data Language

Em que possui comandos para visões, ou seja, um retrato restrito de uma tabela com seus dados. É usado para um relatório, ou quando não queremos exibir muitas informações.

CREATE VIEW EMP_FINANCEIRO AS
SELECT * FROM EMPREGADO
WHERE DNOM = 1

*1 é o ID do Financeiro

DCL: Data Control Language

São os comandos de acesso aos dados a través do BD. Os SGBDs possuem usuários que terão permissão de acesso, e essas permissões podem mudar conforme o usuário.

Com essa linguagem, podemos permitir que usários façam determinadas ações sobre determinadas tabelas, ou podemos liberar todo o BD. Podemos, por exemplo, impedir que determinado usuário não faça exclusão ou inserção registros, mas só consultar, a sublinguagem DCL pode ser usada para conceder ou remover privilégios sobre ações nas tabelas.

GRANT INSERT ON EMPREGADOS TO BRUNO;
GRANT ALL PRIVILEGES
                ON DEPARTAMENTO TO POSTGRES;
REVOKE DELETE ON EMPREGADO FROM BRUNO;
REVOKE ALL PRIVILEGES ON DEPARTAMENTO FROM
  POSTGRES;

Instalando o PostgreSQL em distribuições baseadas no Debian

Para instalar o postgresql no Ubuntu, o primeiro passo é rodar o seguinte comando:

sudo apt install postgresql postgresql-contrib

Em seguida, iniciamos o banco de dados:

sudo systemctl start postgresql

E habilitamos com:

sudo systemctl enable postgresql

E certificamos o status com:

sudo systemctl status postgresql

Esperamos que apareça em Active: active (exited).

Agora, temos que instalar o PgAdmin.

Para isso, vamos ao site e iniciamos instalando a chave pública:

curl -fsS https://www.pgadmin.org/static/packages_pgadmin_org.pub | sudo gpg --dearmor -o /etc/apt/keyrings/packages-pgadmin-org.gpg

Em seguida criamos o repositório:

sudo sh -c 'echo "deb [signed-by=/etc/apt/keyrings/packages-pgadmin-org.gpg] https://ftp.postgresql.org/pub/pgadmin/pgadmin4/apt/$(lsb_release -cs) pgadmin4 main" > /etc/apt/sources.list.d/pgadmin4.list && apt update'

E então instalamos o PgAdmin:

sudo apt install pgadmin4-desktop

Há uma versão web. Se queremos ambas as versões: web e desktop, podemos apenas digitar: sudo apt install pgadmin4

Configurar o PostgreAdmin

Precisamos configurar o PostgreAdmin para se conectar com o Banco de Dados. Para isso, vamos ao terminal para configurar um usuário.

No terminal, digitamos:

sudo -u postgres psql

Dessa forma, acessamos o banco de dados. Nele, vamos adicionar o comando:

ALTER USER postgres WITH PASSWORD 'senha do postgres';

Esse comando diz que desejamos alterar a senha do usuário postgres, que é o usuário default do Banco de Dados. Para isso, precisamos substituir o ‘senha do postgres’ pela senha que desejamos.

Assim, nós configuramos o usuário postgres, e então, vamos fazer com que o PostgresAdmin se conect com o banco de dados. Para isso, vamos no PostgresAdmin.

Na página inicial aparece: Add new Server. Clicamos nele. Irá abrir uma janela em que, na aba General, iremos fazer a nomeação da conexão com qualquer nome. Na aba Connection colocamos como Host name/adress: localhost. Mantemos o nome do banco de dados e do usuário (geralmente ambos como postgres. A senha é a que acabamos de configurar. Clicamos em save e pronto, está configurado.

DDL Create

Principais comandos da Data Defination Language (DDL).

O principal é o CREATE, que faz a criação das tabelas, esquemas, domínios e até das visões.

A ideia de esquema é ser algo como uma coleções de Tabelas, ou seja, diversas tabelas que se relacionam entre si em uma determinada lógica de opeção em um banco de dados. Dessa forma, Um Bancod de Dados pode ser composto por vários Esquemas, e um Esquema pode ser compsoto por várias Tabelas.

No curso trabalhamos com BD mais enchutos, ou seja, um Banco de Dados é um Esquema, que é um grupo de tabelas.

O Comando CREATE TABLE vai criar tabela com atributos (colunas) e restrições iniciais de um modelo relacional. Elas podem ser feitas de três formas:

  1. Dentro do comando, após a declaração de cada atributo;
    1. Dentro do comando, depois que o atributo foi declarado;Com o comando ALTER TABLE.
Tipos de dados de atributos

Numéricos

  • Inteiros de vários tamanhos

  • Pontos flutuantes de várias precisões:

    • Decimal (i,j) ou Numérico (i,j)

      • i - precisão: número de dígitos total

      • j - escala: número de dígitos depois da casa decimal

Por exemplo, um número como 1345,67 é algo como (6,2).

Cadeias de Caracteres

  • Tamanho variável: VARCHAR(n), CHAR VARYING(n), CHARACTER VARYING(n), dessa forma, o n entre parêntese estabelece o número máximo de caracteres dentro do atributo.

  • Valores dos atributos de caracteres precisam ser identificado com aspas simples ’’.

  • Operação de concatenação: ||

    • ‘ABC’ || ‘xyz’ = ABCxyz

Booleano

  • Apenas TRUE e FALSE

Data

  • DATE

    • Data

    • YYYY-MM-DD

  • TIME

    • Tempo

    • HH:MM:SS

  • TIMESTAMP

    • Data e tempo

    • YYYY-MM-DD HH-MM-SS

  • INTERVAL

    • 2 dias, 3 meses…

    • Operadores <> são permitidos.

Então podemos começar a pensar em criar uma tabela. As informações nescessárias podem ser obtidas a partir do Modelo Relacional. As restrições ficam após a declaração de cada atributo.

CREATE TABLE EMPREGADOS(
      NOME VARCHAR(100) NOT NULL,
      CPF VARCHAR(11) PRIMARY KEY,
      DATANASC DATE,
      ENDERECO VARCHAR(30),
      SEXO CHAR,
      SALARIO DECIMAL(12,2),
      SUPERCPF VARCHAR(11) REFERENCES EMPREGADO(CPF),
      DNO INT NOT NULL REFERENCES DEPARTAMENTO(DNUM)
);

Neste caso, falamos que Nome não pode estar vazio. No SQL usamos NOT NULL para identificar um atributo com essa restrição.

O CPF é a chave primária, e é declarado como PRIMARY KEY após identificar o atributo.

Porém, podemos fazer as declarações de restrição, depois de declarar o atributo:

CREATE TABLE EMPREGADOS(
      NOME VARCHAR(100) NOT NULL,
      CPF VARCHAR(11) NOT NULL,
      DATANASC DATE,
      ENDERECO VARCHAR(30),
      SEXO CHAR,
      SALARIO DECIMAL(12,2),
      SUPERCPF VARCHAR(11),
      DNO INT NOT NULL,
PRIMARY KEY(CPF),
FOREING KEY(SUPERCPF) REFERENCES EMPREGADO(CPF),
FOREING KEY(DNO) REFERENCES DEPARTAMENTO()
);

Ou seja, primeiro declaramos os atributos, e depois declaramos as restrições.

Restrições Básicas em SQL

Restrição de Atributo

Se não for permitido algum atributo ficar como NULL, usamos:

  • NOT NULL

  • É uma restrição implícita para a chave primária.

Podemos também declarar um padrão default, ou seja, se ao inserir uma tupla, não declarar valor para um determinado atributo, irá entrar o valor default. Porém, se não for definido um valor default então será NULL.

Podemos também colocar limite em um valor de domínio. Por exemplo:

CREATE TABLE DEPARTAMANTO(
      NOME VARCHAR(50),
      DNUMERO INT NOT NULL,
            CHECK (DNUMERO >0 AND DNUMERO <= 20),
      PRIMARY KEY(DNUMERO)
)

Neste caso, embora declaramos DNUMERO, podemos colocar a cláusula CHECK, para verificar se o valor atende as restrições indicadas dentro do parâmetros, no caso, o número de departamentos necessáriamente precisa estar entre 1 e 20.

Podemos utilizar essa cláusula (CHECK) para verificar a Restrição de Domínio:

CREATE DOMAIN D_NUM AS INTEGER(
      CHECK (DNUMERO >0 AND DNUMERO <=20)
);

CREATE TABLE DEPARTAMENTO(
NOME VARCHAR(50),
DNUMERO D_NUM NOT NULL,
PRIMARY KEY(DNUMERO)
);

Aqui, a cláusula CHECK foi utilizada para criar um domínio, ou seja, que tipo de valor esse atributo vai aceitar. E assim, usamos o D_NUM para armazenar a especificação de domínio.

Restrições de Chave

Especifica se um ou mais atributos serão definidos como Chave Primária da Relação.

Usar o PRIMARY KEY dessa forma é permitido apenas quando temos um atributo como chave primária:

CREATE TABLE DEPARTAMENTO(
      NOME VARCHAR(50),
      DNUMERO PRIMARY KEY
);

Se for composto, devemos definir abaixo ou então usando ALTER TABLE:

CREATE TABLE DEPARTAMENTO(
          NOME VARCHAR(50),
          CPF NOT NULL
          DNUMERO NOT NULL,
      PRIMARY KEY(DNUMERO),
      PRIMARY KEY(CPF)
);

Podemos também declarar as Chaves Alternativas, ou seja, aqueles atributos que também não se repetem, mas não utilizados como Chaves Primarias:

CREATE TABLE ALUNO(
    NOME VARCHAR(50),
    MATRICULA VARCHAR(8) PRIMARY KEY,
    CPF VARCHAR(11) UNIQUE NOT NULL
);

Dessa forma usamos a restrição UNIQUE para caracterizar uma atributo como um atributo que não se repete, que é único.

Restrição de Integridade Referencial

As Restrições de Integridade Referencial podem ser quebradas quando valores da Chave Estrangeira ou Chave Primária forem modificados.

O SGBD tem como padrão rejeitar (RESTRICT)

Por isso, sempre ficar atento pois as rejeições de inserção/modificação podem significar que estamos tentando alterar a CP ou CE.

As Restrições Referencial são a alma dos Modelo Relacional.

Dessa forma:

  • SET NULL ON DELETE

    • Na exclusão, marca nulo

  • SET DEFAULT ON DELETE

    • Na exclusão, define valor padrão

  • CASCADE ON DELETE

    • Na exclusão, propagar

  • SET NULL ON UPDATE

    • Na atualização, marcar nulo

  • SET DEFAULT ON UPDATE

    • Na atualização, definir valor nulo

  • CASCADE ON UPDATE

    • Na atualização, propagar

Exemplo:

CREATE TABLE EMPREGADO(
      ...,
      DNO INT NOT NULL DEFAULT 1,
      CONSTRAINT EMP_PK PRIMARY KEY(CPF),
      CONSTRAINT EMP_SUPER_CPF FORAING KEY(SUPERCPF),
          REFERENCES EMPREGADO(CPF),
          ON DELETE SET NULL ON UPDATE CASCADE,
      CONSTRAINT EMP_DEPT_FK FORAING KEY(DNO),
          REFERENCES DEPARTAMENTO (DNUMERO),
          ON DELETE SET DEFAULT ON UPDATE CASCADE
);

Esse processo é feito após o CREATE TABLE contendo as declarações de atributo, ou seja, após o ....

No caso, estamos fazenddo os dois. Por exemplo, no caso do EMP_DEPT_FK estamos declarando que, em caso de exclusão, será aplicado o valor padrão SET DEFAULT, mas no caso de atualizar, será propagado pelo CASCADE.

CREATE TABLE DEPARTAMENTO(
      ...,
      GER_CPF CHAR(9) NOT NULL DEFAULT '284677398',
      ...
      CONSTRAINT DEPT_PK PRIMARY KEY (DNUMERO),
      CONSTRAINT DEPT_SK UNIQUE (NOME),
      CONSTRAINT DEPT_GER_FK FORAING KEY (GER_CPF),
          REFERENCES EMPREGADO(CPF),
          ON DELETE SET DEFAULT ON UPDATE CASCADE
);

Aqui temos um exemplo de declaração de valor padrão para o GER_CPF.

Outro exemplo de PRIMARY KEY com dois campos:

CREATE TABLE DEP_LOCALIZACOES(
      DNUM INT NOT NULL,
      DLOCALIZACAO VARCHAR(15) NOT NULL,
      PRIMARY KEY (DNUM, DLOCALIZACAO),
      FORAING KEY (DNUM),
          REFERENCES DEPARTAMENTO(DNUM),
          ON DELETE CASCADE ON UPDATE CASCADE
);

Ou seja, não poderia colocar o PRIMARY KEY logo após a declaração de atributos.

A palavra CRONSTRAINT nós temos que indicar o nome dessa restrição. Por isso, uma forma é usar o nome da tabale mais FK pois depois, se precisar eliminar algumas dessas restrições, podemos seguir esse nome.

Podemos ainda fazer uma restrição em todas as tuplas de uma relação. Por exemplo ao criar uma condição para aceitar uma inserção:

CHECK(DEP_DATA_CRIACAO < GERDATAINICIO)

Ou seja, quando for inserir uma tupla em DEPARTAMENTO, teremos que cuidar para que a data do início do gerente seja sempre maior que a data da criação do departamento.

O comando DROP é o comando de exclusão. Só exclui objetos que foram nomeados: Esquemas, Tabelas, Domínios ou Restrições.

Se uma Tabela não é mais nescessária, podemos excluir ela usando o DROP TABLE.

DROP TABLE EMPREGADO CASCADE;

Neste caso, a tabela DEPENDENTE que está vinculada a ela também está vinculada, devido ao comando CASCADE.

Agora se fizermos:

DROP TABLE EMPREGADO RESTRICT;

Impedimos que tabelas vinculada a EMPREGADO sejam escluídas.

Temos também o comando ALTER que permite:

  • Adicionar ou eliminar uma coluna de uma tabela;

  • Alterar o domínio de uma coluna;

  • Adicionar ou eliminar uma restição.

ALTER TABLE EMPRESA.EMPREGADO
    ADD FUNCAO VARCHAR(12);

Para adicionar um atributo em uma relação. Aqui, é um exemplo em que temos um esquema, e dessa forma, fazemos a alteração adicionando primeiro o esquema e depois a relação: EMPRESA.EMPREGADO.

A restrição NOT NULL não é permitida.

Podemos também eliminar uma coluna:

ALTER TABLE EMPRESA.EMPREGAADO
      DROP ENDERECO CASCADE;

E garantimos que irá se propagar ao adicionar o CASCADE.

E podemos alterar domínio também:

ALTER TABLE EMPRESA.EMPREGADO
    ALTER ENDERECO TYPE VARCHAR(100);

Assim, as infromações se mantém, mas elas serão de um novo tipo.

Podemos também eliminar uma restrição:

ALTER TABLE EMPRESA.EMPREGADO
      ALTER GERCPF DROP DEFAULT;

Aqui, estamos eliminando incluir um valor default no atributo GERCPF quando tiver vazio.

E podemos também incluir uma restrição:

ALTER TABLE EMPRESA.EMPREGADO
      ALTER GERCPF SET DEFAULT '372198372';

E apagamos a restrição usando DROP CONSTRAINT:

ALTER TABLE EMPRESA.EMPREGADO
      DROP CONSTRAINT EMP_SUPER_CPF CASCADE;

Criando um Banco de Dados

Dessa forma, vamos utilziar alguns comandos para construir um banco de dados relacionais semelhante ao que está no livro Sistema de Banco de Dados (Elmasri e Navathe, 2011) na página 48.

Começamos por criar a tabela funcionários

CREATE TABLE funcionario(

unome           varchar(30),
cpf             varchar(11),
datanasc        date,
endereco        varchar(100),
sexo            char,
salario         decimal(10,2),
cpf_supervisor  varchar(11),
dnr             integer,
PRIMARY KEY(cpf)
);

Agora a tabela departamento:

CREATE TABLE departamento(
dnome           varchar(30),
dnumero         integer,
cpf_gerente     varchar(11),
data_inicio_gerente date,
PRIMARY KEY(dnumero)
);

E a tabela dependente:

CREATE TABLE dependente(
fcpf            varchar(11),
nome_dependente varchar(50),
sexo            char,
datanasc        date,
parentesco      varchar(50),
PRIMARY KEY(fcpf, nome_dependente)
);

Projeto;

CREATE TABLE projeto(

Onde trabalha:

-- trabalha_em
CREATE TABLE trabalha_em(

horas           decimal(5,1),
PRIMARY KEY(fcpf, pnr)
);

E departamento:

CREATE TABLE localizacao_dep(
dnumero     integer,
dlocal          varchar(50),
PRIMARY KEY(dnumero, dlocal)
);

E depois, alteramos para incluir as chaves extrangeiras. A ideia é que, se tivessemos declarado durante a criação (ou seja, CREATE TABLE), precisariamos que a tabela da onde extraímos a chave estrageira já tivesse sido criada, mas ela também tem chave estrangeira. Portanto, criamos após o CREATE TABLE.

ALTER TABLE funcionario ADD CONSTRAINT dep_func_fk FOREIGN KEY(dnr) REFERENCES departamento(dnumero);

Vamos utilizar agora a DML para minupular os dados criado na seção anterior. Note que, antes de tudo, precisamos criar a estrutura da tabela, declarando os atributos, os domínios e a chave primária e estrangeira. Em seguida, podemos dar continuidade a manipulação de dados.

DQL - Data Query Language

Consultas Básicas

Esta é a sublinguagem para consultas. Esta é a parte que mais utilizamos, uma vez que é através dela que nós realizamos a maior parte da interação com o Banco de Dados, para acessar as informações presente neles.

Aqui nós vamos continuar com o Banco de Dados Empresa. Porém, mesclando a linguagem R com SQL.

A forma mais básica de se fazer uma consuta é através do SELECT, com a seguinte estrutura:

SELECT <lista de atributos>
FROM <lista de tabelas>
WHERE <condição>

Aqui, após o SELECT temos a lista de atributos, ou seja, todas as tabelas que queremos que esse comando nos devolva. O FROM é a lista de tabelas. Pode ser um ou mais, e é onde esses atributos tem que existir. E o WHERE é a condição, ou seja, quais registros vamos trazer.

Os operadores mais comuns são: =, <, > <=, >=, e <>.

Consultas Avançadas

Aqui, há a incrementação de novos operadores, novas cláusulas que permite consultas mais sofisticadas.

Joins

É geralmente utilizado nos comandos de consultas (i.e. SELECT). E permite selecionar dados que estão armazenados nas nossas tabelas de modo que eles sejam reestruturados e gerem novas tabelas temporárias mostrando o que foi solicitado.

Uma vez que estamos em banco de dados relacionais, nossas consultas permite agregar diferentes tabelas. Aqui, a chave estrangeira é a responsável por fazer a interligação entre tabelas e permite fazer a agregação.

Os joins são praticamente a alma, e portanto precisam ser bem intendidos.

Os JOINS são estruturados da seguinte maneira: o FROM vem da tabela que possui as chaves primárias, e os JOIN vem das tabelas que possui as chaves estrangeiras. Nós podemos fazer JOIN com várias tabelas, desde que elas possuem as chaves estrangeiras. E o ON faz justamente esse apontamento: da chave primária para a chave estrangeira, e por isso possui o sinal de igualdade.

É importante destacar que o mesmo poderia ser feito com o seguinte comando:

SELECT NOME, COR, MODELO
FROM AUTOMOVEL, UNIDADE
WHERE COD_AUTO = CODAUTO AND COD_AUTO = '18';
  nome    cor              modelo
1 Golf  Prata    Highline 1.4 TSI

Porém, essa é uma sintaxe antiga. Utilizar o JOIN juntamente com o WHERE deixa a escrita mais organizada, uma vez que o ON deixa claro como as tabelas se relacionam, e WHERE deixa claro a condição.

Comparações e Funções com NULL

O NULL pode ter alguns significados em Banco de dados. Ele pode significar:

  • Valor desconhecido: ou seja, esse valor existe mas não conhecemos. Um exemplo seria a data de nascimento de um funcionário.

  • Valor indisponível: uma informação que existe mas está, proporcionalmente omitida. Exemplo: endereço de email de um funcionário

  • Valor não aplicável: indefinido para determinada tupla. Um exemplo poderia ser uma segunda graduação.

Dessa forma, um NULL sempre será diferente de outro NULL, são considerados valores diferentesentre si: NULL != NULL.

Dessa forma, para saber se algo é NULL, não devemos perguntar se algo é NULL usando o símbulo de igualdade (=). Devemos usar as seguintes expressões:

  • IS NULL -> equivalente a =

  • IS NOT NULL -> equivalente a <>

Por exemplo, se queremos saber se há algum funcionário não tem a data de nascimento preenchida, devemos fazer assim:

SELECT *
FROM funcionario
WHERE datanasc IS NULL
 [1] pnome          minicial       unome          cpf            datanasc      
 [6] endereco       sexo           salario        cpf_supervisor dnr           
<0 rows> (or 0-length row.names)

Há outra função chamada COALESCE que verifica os valores da expressão e retorna o primeiro valor não nulo:

SELECT COALESCE(fone_1, fone_2, fone_3) FROM aluno

Neste exemplo, queremos o telefone do aluno. Mas há três campos que este telefone pode estar, no fone_1, fone_2 e fone_3. Porém, em um caso onde o aluno possui apenas um número, e não sabemos em qual campo ele foi inserido, podemos usar a função COALESCE que, dentro dos três campos, vai retornar o primeiro que não tem valor NULL.

Converte as letras da cadeia de caracteres em minúsculas:

SELECT LOWER(nome_usuario)

Converte a primeira letra de cada palavra em maíuscula, e as demais em minúscula:

  • 3º parâmetro da função: comprimento da substring

SELECT SUBSTR(nome, 2, 4)

Neste caso, vai selecionar 4 caracteres mas irá começar a contar a partir do segundo.

Tem como objetivo exibir o número de caracteres presentes na string:

SELECT REPLACE(nome, 'R', 'K')
FROM professor;

Pode ser utilizada para realizar correções, ou atualizações. Neste caso, todas as strings que iniciam com R serão substituídas pelo K.

Funções de Correspondência

Nas funções de correspondência temos a função LIKE e ILIKE. Elas verificam se determinada string está contida no conjunto de strings representado por determinado padrão. que será especificado.

LIKE é case sensitive, ou seja, ele faz distinção entre maíscula e minúscula.

ILIKE não é case sensitive, ou seja, não faz distinção entre maíscula e minúscula.

Nós podemos definir “coringas” para definir o padrão a ser comparado:

% significa qualquer quantidade de caracteres

_ significa apenas um caractere

Utilizando a base de dados locadora, podemos verificar o nome de carros que começam com a letra R:

FROM automovel
WHERE nome LIKE 'R%'

1       19 Renegade            1             2

Ou podemos verificar carros que terminam com a letra f:

SELECT * 
FROM automovel
WHERE nome LIKE '%f'
  cod_auto nome id_categoria id_fabricante
1       18 Golf            2             4

Ou pro exemplo, buscar nomes de carros que tenham a combinação ya:

SELECT * 
FROM automovel
WHERE nome LIKE '%ya%';
  cod_auto   nome id_categoria id_fabricante
1       17 Voyage            3             4

Usando o coringa _ a busca é referente a apenas um caracter:

SELECT * 
FROM automovel
WHERE nome LIKE '_olf';
  cod_auto nome id_categoria id_fabricante

Nós podemos combinar a busca com os dois:

SELECT * 
FROM automovel

O fato de não usarmos o singal de = com string é que pode haver uma grande variação de digitação, e portanto, essas funções entram como alternativas.

Operações sobre Conjuntos

Essas operações visam apresentar como devemos realizar consultas para tratar os resultados como conjuntos de elementos.

É similar a ideia de “somar” ou “subtrair” registros de duas ou mais consultas:

Um ponto importante é que as consultas precisam ter o mesmo número de colunas para cada tabela. Elas precisam também serem equivalentes, ou seja, os dados precisam ser do mesmo tipo também (i.e. varchar com varchar, integer com integer).

Para isso, temos algumas operações:

UNION que faz a união entre conjuntos;

INTERSECT que faz a interseção entre conjuntos; e

EXCEPT que faz a diferença de uma consulta.

O UNION faz a união entre os resultados de dois SELECT. Essa união é feito pelas linhas, ou seja, uma linha abaixo da outra, como se estivesse empilhando os resultados das duas consultas. Linhas repetidas são ignoradas.

Sendo assim, as colunas precisam, além de serem equivalentes, terem os mesmos nomes, certo?

O Comando UNION ALL as linhas reptidas são exibidas.

Não confundir UNION con JOIN

Enquanto o JOIN é a junção entre colunas de tabelas diferentes seguindo uma condição, o UNION é a união das tuplas de duas tabelas.

O INTERSECT realiza as interseção o resultado de dois SELECT, e a interseção é também feita entre linhas de ambos os resutlados. Aqui também as linhas repetidas serão ignoradas. Porém, com o comando INTERSECT ALL as linhas repetidas serão exibidas.

O EXCEPT realiza as diferenças entre os resultados do SELECT. As diferenças é entre as linhas, ou seja, as linhas que estão em um resultado que não estão em outro resultado. As linhas repetidas são ignoradas, mas com EXCEPT ALL, as linhas repetidas serão exibidas.

Funções de Agregação e Agrupamento

Funções de Agregação

Tem como objetivo, obter informações sobre o conjunto de linhas especificadas na cláusula WHERE ou sobre grupos de linhas (GROUP BY).

  • COUNT

  • MAX

  • MIN

  • SUM

  • AVG

Quando aplicamos uma função de agregação, o resultado é apenas apenas uma tupla em que as informações estão armazenadas conforme o seu objetivo.

Se utilizamos a palavra DISTINCT dentro do parêntese de uma função de agregação, executa a função ignorando as repetições.

Os valores NULL são ignorados pelas funções de agregação.

A função COUNT vai devolver o número de linhas que resultam de um SELECT. Ela pode ser feita de algumas maneiras:

  • COUNT (*) - devolve o nº de linhas que resulta de um SELECT

  • COUNT (coluna) - devolve o nº de ocorrências na coluna diferentes de NULL

  • COUNT (DISTINCT coluna) - devolve o nº de ocorrências (sem repetição) na coluna

Vamos considerar o banco de dados empresa.

Se queremos saber a quantidade de funcionários na empresa, podemos rodar o seguinte comando (lembrando que AS é o “apelido” que quermos mostrar nos resultados):

SELECT COUNT(*) AS total
FROM funcionario
  total
1     8

O resultado será, obviamente, o número de tuplas.

Mas podemos também verificar funcionarios que recebem um salário maior que R$5.000,00:

SELECT COUNT(*) AS maiores
FROM funcionario
WHERE salario > 5000;
  maiores
1       8

Se quisermos saber quantos supervisor temos na empresa:

SELECT COUNT(DISTINCT cpf_supervisor) AS sup
FROM funcionario;
  sup
1   3

Uma pessoa pode supervisionar mais de um funcionário, dessa forma, usamos DISTINCT para retirar os CPFs repitidos.

Função Min e Max

Permitem selecionar o menor e o maior valor que está armazenado em um determinado atributo.

Essas funções podem ser aplicadas a atributos que não contenham valores numéricos. Uma vez que o SQL permite trabalhar de uma maneira “matemática” os dados, podemos utilizar essas funções para ordenar por órdem alfabética, ou cronológica.

Por exemplo, se queremos saber a menor hora trabalhada na empresa

SELECT MIN(horas) AS min_horas
FROM trabalha_em
  min_horas
1         5

Ou se queremos saber quem é mais velhor:

SELECT MIN(datanasc) AS mais_velho
FROM funcionario;
  mais_velho
1 1937-11-10

É interessante na função de agregação utilizar um “apelido” que mostre a aplicabilidade da consulta, ou seja, para quê estamos fazendo.

Alguns exemplos com a função MAX:

Para saber o maior salário:

SELECT MAX(salario) AS maior_salario
FROM funcionario;
  maior_salario
1         55000

Ou para consultar a data em que a ultima pessoa assumiu como gerente:

SELECT MAX(data_inicio_gerente) AS ultimo
FROM departamento;
      ultimo
1 1995-01-01

Função Sum

Devolve a soma dos valores de uma determinada coluna. Só pode ser aplicado a campos numéricos.

Se quiser saber o total da folha de pagamento:

SELECT SUM(salario) AS total_folha
FROM funcionario;
  total_folha
1      281000

E se eu quiser calcular um aumento de 10% para todos aqueles funcionários que ganham menos que R$ 30.000,00?

SELECT SUM(salario*1.1) AS nova_folha
FROM funcionario
WHERE salario < 2000
  nova_folha
1      82500

Entrega a média de valores de determinado atributo. Também só pode eser aplicado a campo numérico.

Por exemplo:

Qual a média de horas que os funcionários estão vinculado ao projeto?

SELECT AVG(horas) AS media_horas
FROM trabalha_em;
  media_horas
1    18.33333

Ou se quiser saber a média de salário:

1         35125

Função de Agrupamentos

Para aumentar o potencial de consulta, há as funções de agrupamentos. Geralmente, as funções de agrupamentos são aplicadas em informações de forma agrupada, não como um todo. Ou seja, geralmente não será aplicado para todas as tuplas, pois o objetivo é agrupar.

Possibilita aplicar a funções de agregação a grupos menores de informações.

Para isso, temos duas funções:

  • GROUP BY; e

  • HAVING

Com essas funções a estrutura do SELECT precisa ficar nescessáriamente da seguinte maneira, se não, não irá funcionar:

SELECT <campos>
FROM <tabela>
WHERE <condição>
GROUP BY <agrupamentos>
HAVING <condição aos grupos>
ORDER BY <se quiser ordenar>

Gourp by

A cláusula GROUP BY possibilita agrupar as informações ao utilizar funções de agregação. Ou seja, ela dividi o resultado de uma função de agregação em agrupamentos. Como resultado, teremos um valor de função de agregação para cada grupo.

Todas as colunas selecionadas precisam estar presentes no GROUP BY.

Por exemplo:

Se queremos fazer uma contagem de funcionario (ou seja, um CPF - é importante usar a chave primária para fazer essa operação), e essa contagem é por departamento. Para isso, vamos fazer:

SELECT dnr, COUNT(cpf) AS num_func
FROM funcionario
GROUP BY dnr
  dnr num_func
1   5        4
2   4        3
3   1        1

Se eu quiser saber quanto cada funcionario dedica para cada projeto podemos fazer:

SELECT pnr, SUM(horas) AS num_horas
FROM trabalha_em
GROUP BY pnr
  pnr num_horas
1  30      55.0
2   3      50.0
3  10      55.0
4   2      37.5
5  20      25.0
6   1      52.5

Podemos tentar também uma consulta para saber quantos dependente cada funcionário possui:

SELECT cpf, pnome || unome, COUNT(*)
FROM DEPENDENTE
JOIN funcionario ON (cpf == fcpf)
GROUP BY cpf, pnome, unome;

1 12345678966     JoãoSilva     3
2 33344555587  FernandoWong     3
3 98765432168 JenniferSouza     1

Dessa forma sabemos quantos dependentes cada funcionário possui.

Todos os gruos presentes no SELECT que não estão na função de agregação, obrigatoriamente precisam estar no GROUP BY.

Having

A cláusula HAVING efetua restrições ao nível dos grupos que estão sendo processados. Ele atua sobre o resultados dos grupos.

Exemplo:

Se queremos saber quantos CPFs existem por departamento, podemos fazer:

SELECT dnr, COUNT(cpf) AS num_func
FROM funcionario
GROUP BY dnr
HAVING COUNT(cpf) > 10
  dnr num_func
1   5        4
2   4        3
3   1        1

Mas vejamos que só queremos departamento em que a contagem é menor que 10. Muito importante ter em mente que a restrição é para o grupo que acaba de ser formado com o GROUP BY.

Novamente:

Quando utilizar:

  • WHERE - quando se pretende restringir os registros (as tuplas) a ser considerados na seleção.

  • HAVING - quando se pretende restringir a partir dos grupos que foram formados.

Não se pode usar funções de agregação na cláusula WHERE.

Em resumo:

  • A cláusula WHERE só pode ser aplicada a registros individuais;

  • A cláusula HAVING só pode ser aplicada a função de grupo.

Por exemplo:

Se queremos saber quantos dependentes de funcionarios nascido a partir de 1950 que possuem mais de 2 dependentes, aplicamos:

SELECT cpf, pnome || unome, COUNT(*)
FROM dependente
JOIN funcionario ON (cpf = fcpf)
WHERE datanasc < '1969-01-01'
GROUP BY cpf, pnome, unome
HAVING COUNT(*) > 2
          cpf     ?column? count
1 12345678966    JoãoSilva     3
2 33344555587 FernandoWong     3

É sempre bom, nestes casos, usar aliases. Neste exemplo acima, datnasc esta presente nas duas tabelas. Usando aliases facilita determinar exatamente de qual tabela estamos usando o atributo.

E o que acontece quando os dados agrupados de uma coluna que dentre eles existe o valor NULL?

Em um SELECT com cláusula GROUP BY, se existirem NULL na coluna de agrupamento, estes também são agrupados.

Subconsultas - Subquery

São mais uma ferramenta para construir consultas mais complexas e atender nossas nescessidades na hora de obter dados dos SGBDs.

O comando SELECT retorna o resultado em forma de tabela temporária. São atribuídos nomes as tabelas desta consulta. Nós podemos incorporar esses resultados em outro comando SELECT e é desta forma que geramos uma subconsulta. Ou seja, Um SELECT dentro de outro SELECT.

Dessa forma, o Query é estruturado da seguinte maneira:

SELECT <campo>
FROM <tabela>
WHERE <condição> =
      (
      SELECT <campo>, <funcao>
      FROM <tabela>
      )

Um comando SELECT pode ser alocado:

  • Dentro de um outro SELECT, nas cláusulas WHERE, HAVING, SELECT e FROM;

  • Dentro de umaa outra subconsulta nas mesmas cláusulas do intem anterior;

  • Nos comandos INSERT, UPDATE e DELETE;

  • Na definição de VIEW

Mas na prática, comos implementamos estas subconsulta?

Se temos um problema: Qual é o nome do funcionário com o menor salário na empresa?

A solução passa por duas etapas:

  1. Qual é o valor do menor salário?
  2. Qual é o nome do funcionário que recebe este salário?

Vamos seguir passo a passo:

Etapa 1:

SELECT MIN(salario) AS menor_salario
FROM funcionario;
  menor_salario
1         25000

Etapa 2:

SELECT nome, unome, salario
FROM funcionario
WHERE salario = 25000;
  pnome   unome salario
1 Alice  Zelaya   25000
2 Joice   Leite   25000
3 André Pereira   25000

Temos então os funcionários com os menores salários.

Mas podemos fazer de uma forma que fique estruturado em apenas uma consulta, sem precisar primeiro descobrir qual o menor salário, para então descobrir o nome.

Para isso, precisamos transpor a consulta sobre o menor salário na consulta sobre o nome do funcionário:

SELECT pnome, unome, salario
FROM funcionario
WHERE salario = 
          (
          SELECT MIN(salario)
          FROM funcionario
          );
  pnome   unome salario
1 Alice  Zelaya   25000
2 Joice   Leite   25000
3 André Pereira   25000

Subconsulta correlacionada

É a subconsulta que, para seu funcionamento, depende de consultas mais externa. O SELECT interno (da subconsulta) tem que considerar um conjunto específico de registros que está sendo analisado individualmente pelo SELECT externo. A ligação entre os dois SELECT é feita pelo WHERE.

Por exemplo:

Se queremos saber o nome dos vendedores cujo salário é menor do que 15 vezes a soma de suas próprias comissões:

SELECT nome, salario
FROM vendedor v
WHERE salario < (
        SELECT SUM(valor)
        FROM comissao c
        WHERE v.id = c.id * 15
)

Podemos ver que a ligação está justamente no id, que representa a chave primária e permite identificar o vendedor.

Subconsulta não-correlacionada

Mas há também a subconstula não-correlacionada, quando a consulta não depende de valores da consulta extra:

SELECT pnome, salario
FROM funcionario
WHERE salario = (
      SELECT MAX(salario)
      from funcionario
);
  pnome salario
1 Jorge   55000

Ou seja, a consulta não depende de valores sobre a cosulta externa.

Em resumo:

Funcionamento Consultas não-correlacionadas Consultas correlacionadas
Sentido da execução Da interna para a externa Da externa para a interna
Dependência da consulta interna Não depende da consulta externa Depende da consulta externa
Execução da consulta interna Uma única vez Tantas vezes quanto forem executadas pela consulta externa

Operadores IN

Os operadores IN permite verificar se um valor existe dentro de uma coluna ou conjunto de valores dentro de um parêntese. Se temos quatro possíveis valores, podemos saber se um determinado valor está dentro desses quatro valores.

Nas subconsultas, podemos verificar se o valor está no resultado de uma subconsulta, retornando TRUE ou FALSE.

Por exemplo, se queremos saber quais clientes cadastrados residem em Veranópolis:

SELECT nome, cep
FROM cliente
WHERE cep IN (
      SELECT cep
      FROM endereco
      WHERE cidade = 'Veranópolis'
);

Há também o NOT IN que é a ideia inversa:

SELECT nome, telefone
FROM cliente
WHERE id_cliente NOT IN (
    SELECT id_cliente
    FROM compra
);

Operador Exists

Este operador verifica se a execução da subconsulta gerou ou não alguma linha de resultado, retornando TRUE ou FALSE. A estrutura é a seguinte:

SELECT <campos>
FROM <tabela>
WHERE  [NOT] EXISTS (<subsonculta>)

O operador nunca é precedido por qualquer coluna ou expressão. Como devolve apenas TRUE ou FALSE, as subconsultas associadas são geralmente do tipo SELECT * FROM.

Por exemplo, se queremos o nome dos vendedores que tem comissões a receber:

SELECT nome
FROM funcionario f
WHERE EXISTS (
    SELECT * FROM comissao c
    WHERE f.id = c.id
)

Operador ALL e ANY

Operadores que podem ser adicionados a comparações que utilizem os operadores relacionais =, <, >, <=, >=, <>

Permitem realizar comparações com o seguinte formato:

<expressao> operador ALL (subconsulta)
<expressao> operador ANY (subconsulta)
Operador ALL

O resultado é verdadeiro se, para cada um dos valores resutlantes da subconsulta, a expressão devolver o valor lógico verdadeiro.

SELECT nome, datanasc
FROM cliente
WHERE cep <> ALL (
      SELECT cep FROM endereco
      WHERE cidade = 'Veranópolis'
);

Esta consulta seleciona clientes que não residem em Veranópolis.

Operador ANY

O resultado é verdadeiro se, para qualquer dos valores resultantes da subconsulta, a expressão retnorna o valor lógico verdadeiro.

SELECT nome, datanasc
FROM cliente
WHERE cep = ANY (
      SELECT cep FROM endereco
      WHERE cidade <> 'Veranópolis'
)

Uma dica é que quando a subconsulta depende de valores externos (subconsultas não correlacionada), nós devemos execultar primeiro a subconsulta para verificar se corresponde ao que queremos e depois construímos a consulta toda.
